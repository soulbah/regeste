- 2026-07-12 — Multi-file ingest: whole selection appears at once, indexes in parallel (owner: "si j'ajoute 10 fichiers... ils n'apparaissent qu'un à un, c'est contre-intuitif"). The upload handlers looped `await ingest(file)`, so each file was fully parsed+embedded before the next was even inserted — rows trickled in one by one. Split ingest into `stageDocument` (hash + dedup + insert a pending row) and `processDocument` (parse → chunk → embed → index), and added `ingestMany`: it stages every file first (all rows appear immediately as `received`), returns the ids right away so callers can attach them, then processes in the background through a concurrency-limited runner (`processMany`, 3 at a time — the single embed worker still serializes the heavy step, so this overlaps parsing with embedding without thrashing). Bytes are re-read from the File at process time, so a batch of large PDFs never holds every file in memory at once. All four upload paths (documents page, chat home, chat thread, chat documents panel) use it. Verified live: 6 files staged in 66 ms (all shown `received` at once), then indexed 3-at-a-time (`embedding: 3, received: 3`), all `ready` at 2.3 s. `bun run verify` green.
